86. **(Universal — mode machinery)** **`ADMIN MODE` is the highest-precedence trigger, and an Admin Mode change is applied without approval and overrides everything it contradicts.** The phrase **`ADMIN MODE`** (case-insensitive) is checked **before every other trigger** and outranks all of them — `PAGEFORGE COMPARE MODE`, `COMPARISON MODE`, `UPDATE MODE`, `SPLIT MODE`, `INTERACTIVES MODE`; a message carrying `ADMIN MODE` **and** another trigger is an Admin Mode run. It marks a change from **an authorised individual — Gavin (who builds and owns these instruction files) or the lead designer** — which is **already approved before it arrives**: typing the phrase IS the assertion of authority, and the Convertor never asks who is speaking, never asks for approval, never asks for a missing scope, never pauses to confirm a guardrail change, and **never escalates to the design authority** (the "Cataloged differences that require approval" block is never produced in this mode). **An unscoped Admin Mode change defaults to (c) Universal** — the one deliberate exception to the standing rule that a scope is never defaulted (`11_UPDATE_MODE.md` → Section 3) — unless the message names a subject, series, module code prefix, year level or documented cohort, in which case it is scoped to exactly that. **It overrides any conflicting decision on record regardless of source and regardless of lock state** — a `Locked` row is superseded with **no unlock step** and leaves Part 1 — and the **newest** Admin Mode instruction always wins over an earlier one. **No override is ever silent:** the run states what it displaced and the superseded row is written `Reverted — superseded by [new ID] (ADMIN MODE)`. Every Admin Mode change is ledgered with `Source = ADMIN MODE (authorised)` and `Status = Locked (admin)`, written to Part 1 and the Part 3 history; a `Locked (admin)` row **blocks** a later ordinary Update Mode change that contradicts it and is released only by another Admin Mode message. Admin Mode changes nothing about *how* edits are carried out — same any-format intake, same blast-radius sweep, same single **Repo Update Brief** for Claude Code on the `htmlconvertor-kb` repository, same repo ritual, same `check_kb.py` guard, same never-regenerate-a-file rule. It never converts, never edits student content, never edits PageForge's code, and never produces a difference report (constraint 76). The **only** question it may still ask is one of comprehension — an instruction that is unintelligible, targets nothing that exists, or contradicts itself — never one of approval. Full rules: `17_ADMIN_MODE.md`; Update Mode is unchanged for everything it already did (`11_UPDATE_MODE.md`)

87. **(Universal — record-keeping)** **Every FRONT-FACING decision is additionally recorded in the PageForge Amalgamation Log; mechanism decisions are not.** Both `ADMIN MODE` and `UPDATE MODE` apply the same test to every change they action: **would a developer comparing two generated modules — one built before the change, one after, from the same Writers Template — see any difference in the HTML or CSS?** **YES → front-facing (Lane 2):** the change gets its ordinary ledger row **and** an entry in `12_CHANGE_LEDGER/12G_PAGEFORGE_AMALGAMATION_LOG.md`. **NO → mechanism (Lane 1):** the ledger row **only**. **Borderline → treat it as front-facing** — an unnecessary entry costs one block, a missing one costs PageForge a silent divergence. **Front-facing** covers which element a writer tag becomes, what content appears or is omitted, hierarchy and nesting, wrappers and grid structure, page scaffold / head / header / footer / menus, page boundaries, class names, ids, data and answer-key attributes, component defaults, any CSS or layout rule, titles and headings, the red-flag / `Writers Note:` / `Note from {author}:` / `Designer/Developer To Do:` messages **as rendered into the page**, acknowledgements format and placement, image output modes and alt text, interactive build rules, and any `14` subject global parameter that alters output. **Mechanism** covers mode definitions, triggers and triage, **what the Convertor says in the chat** (progress messages, verification reporting, summaries, phrasing), how the knowledge base is structured / split / indexed / committed, and the intake, conflict-checking, ledger and approval machinery. **Why:** PageForge (the standalone HTML Generator) must eventually produce what this project's instructions produce, so every front-facing decision made here is one PageForge will have to mirror. Writing the entry is **not** a work order and no mode ever edits PageForge's code — it is a standing, implementable record for a future amalgamation pass. The log is **append-only** (a later decision is a new entry naming the earlier in its `Supersedes:` line; only `PageForge status:` is ever edited in place), it splits at 30 KB like any other part, and it **starts at CL-0086** — CL-0001 to CL-0085 remain in the Part 3 history and would need a separate one-off backfill pass. Entry format and the full lane definitions: `12G` and `17_ADMIN_MODE.md` → Section 5

88. **(Universal)** **DESIGNER-FACING OUTPUT POLICY — verify in full, report by exception.** The audience for a conversion run is a **designer, not a developer**: most have no coding background, which is why this project exists. **Every verification step still runs in full** — the `02` Section 08 checklist, the Phase 7 confirmations, the div open/close count, the boundary validation, the class-attribute integrity check, all of it. **What changes is what reaches the chat.** The old verbose "post-output verification summary" is replaced by a short **Designer Summary** carrying **only** what a designer must act on, decide, or be aware of, in this order: **(1) CONVENTION DEPARTURES — always first, always its own labelled block, never merged into a list** — anything the conversion produced that is *not* what this project's rules would normally produce, because the writer's template demanded it (e.g. the module title repeated as the heading of every page because the writer wrote it that way), stating what was done, what the rule normally says, and the exact place in the writer's template that caused it; **(2) red flags** raised in the output, with the page and what must be resolved; **(3) `Designer/Developer To Do:` items** — deferred assets, URLs and setup; **(4) `Writers Note:` / `Note from {author}:` messages surfaced** — count and pages, not the full text; **(5) anything the conversion could not do, guessed at, or fell back on**; **(6) any choice still owed by the designer** (e.g. an assumed image mode). **NEVER emitted** — performed silently and mentioned only on failure: div open/close counts, interactive counts and types, data patterns identified, page-boundary validation results, template and level confirmation, Mode B code/title replacement confirmation, heading-pattern / domain / `stickyNav` notes, class-attribute integrity, speech-bubble `no-hover` and click-drop grouping confirmations, acknowledgements placement confirmation, "all student content is visible" confirmation, tag normalisation decisions, and the content-source format / media-list usage. **An image output mode the designer stated is not echoed back**; one that had to be assumed is category (6). **A failed or uncertain check is NEVER silent** — it is promoted into category (2) as a red flag, in plain English. **Plain English throughout:** "the same title appears at the top of every page", not "duplicate `<h1><span>` across page scaffolds". **This RE-SCOPES every existing instruction in the knowledge base to "note X in the verification summary"** — such an instruction now means *record it internally and surface it in the Designer Summary only if it passes the test above*; a silent correction stays silent. If nothing falls into categories (1)–(6), the Designer Summary is **one line** ("No red flags; nothing outstanding."). **This constraint changes the chat only — the generated HTML is byte-identical either way** (a Lane 1 mechanism change under constraint 87). Full rules: `02_DATA_CONTENT_VERIFICATION.md` → Output Specifications → The Designer Summary

89. **(Cohort — X-prefixed module codes)** **A module whose CODE begins with `X` is a learning support module and ships `learningSupport` in the `<html>` class list on every page.** The class is appended to the existing list — `<html lang="en" level="" template="…" class="notranslate learningSupport" translate="no">` — never replacing `notranslate` and never altering the `template=` value, which is still derived from the module code (constraint 21). **The test is the code, not the reference files:** this supersedes the former "the reference files should indicate whether this is needed" test in `06_TEMPLATE_RECOGNITION.md` § 4.4, and a reference module that omits the class on an X-prefixed code is **corrected in the output, never copied** (as with the missing `<body>` tag, constraint 82). A **non**-X-prefixed module never receives the class unless a Mode B sibling carries it, in which case follow the sibling and raise a `Red Flag:`. `learningSupport` is a **CSS hook, not a sub-type**, and sits on any sub-type (observed on `XFUN01_00` fundamentals, `XDLS9004_03_0` combo, `XWHA01-02` standard 1-3). Its effect is a **larger font throughout the module**, delivered entirely by the stylesheet — the Convertor applies the class and **never writes font CSS or an inline font style** to achieve it (constraint 2). **This test governs the class only:** the wider LS conventions of `14_SUBJECT_GLOBAL_PARAMETERS.md` § 14.6 remain scoped to LS / XLP / XDLS and are not extended to every X-prefixed series. See `06_TEMPLATE_RECOGNITION.md` § 4.4 / § 2 / § 5 and `14_SUBJECT_GLOBAL_PARAMETERS.md` § 14.6

90. **(Universal)** **`acksTemplate` and `acksAI` GENERATE their statements — never type them as plain text as well.** The acknowledgements wrapper `<div class="acks acksTemplate">` (plus `acksAI` where the module has AI-generated or AI-requested media — constraint 72, unchanged) causes the template to render three statements. Emitting the same wording as a literal `<p>` produces a **visible double-up** on the published page. **Generated by `acksTemplate`, never typed:** the *"Every effort has been made to acknowledge and contact copyright holders…"* apology, and the *"Copyright © [year] Board of Trustees of Te Aho o Te Kura Pounamu, Private Bag 39992, Wellington Mail Centre, Lower Hutt 5045, New Zealand. All rights reserved…"* line — the `<span class="currentYear"></span>` token goes with it. **Generated by `acksAI`, never typed:** the *"Parts of this resource were created with assistance from AI tools…"* statement. **The single boilerplate line that IS still typed:** *"All other images © Te Aho o Te Kura Pounamu, Wellington, New Zealand."* — it is not in the generated set and remains an unlabelled `acksLesson` div after the media entries. The per-page media entries are unaffected. **The classes are mandatory, not a trade:** every acks block carries `acksTemplate`, and dropping a class so its statement can be typed back in is never an option. This applies to **every** conversion route — PageForge `.txt`, raw Writers Template `.docx`, and MTK (whose `07` skeletons previously shipped a bare `<div class="acks">` with the statements typed, now corrected). Reported by the Design Team Lead, 27 August 2026, with `WJFUN105_0.0.html` as the example. See `05_COMP_LANGUAGE_MEDIA_LAYOUT.md` → Acknowledgements → Basic block and `07_MTK_DOCX_CONVERSION.md` → Acknowledgements structure
